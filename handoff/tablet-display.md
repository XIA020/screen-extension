# 屏幕扩展发布交接

- 分支为 `main`。最近验证环境为 Windows 11 x64、MatePad 和 GT6。根目录 README 提供安装、连接与构建步骤。
- 已验证两台设备在同一热点上分别使用独立副屏，单独断开 GT6 时 MatePad 串流继续。MatePad 已实测在活动串流中从复制切回扩展。GT6 使用 2200×1000 桌面、2780×1264 原生全屏串流，用户确认两侧黑边消失。
- 第二路启停保留已有屏幕位置。Windows 调整模式后先等待系统完成排列再校正。已用两台在线设备往返切换 1920×1080 和 2200×1000 验证位置。
- 后续重点是干净主机的双路安装、共用 MTT 适配器时的独立停用，以及两台设备同时在线时从复制恢复扩展。安卓直接点主机也需要单独验收。
- 两端运行配置和配对记录随设备本地保存。Android 正式签名密钥由发布者保管。调试、构建和安装包的生成规则见根目录 README。

## v0.2.0 候选版

- 2026 年 11 月 18 日，最近工作设备为当前 Windows 台式机。候选分支为 `next/wired-reconnect`，Windows 安装包、正式签名的安卓 12.7（320）和 SHA-256 位于 `D:/TabletDisplayTest/NextVersion-0.2.0`。候选版尚未发布，公开下载库不引用此构建。
- 正式配对后，安卓在首次手动确认新版邀请并成功走已配对 TLS 后记住电脑的邀请公钥。重连需验证签名和一次性挑战，并用已配对的 Sunshine 证书建立 TLS。已有配对升级后只需额外确认一次，现有旧协议仍弹确认框。安卓需停在应用首页。
- 控制台「扫描 USB 设备」会寻找支持 USB 共享网络的网卡，同一条网卡发送邀请并承载串流。Windows 没有可用热点时仍可打开控制台。目前 MatePad 连接数据线后只观察到 MTP、ADB 等功能和无线接口，未出现 USB 网络接口。需找支持 USB 共享网络的设备做真机验收，并测量延迟。
- 两端构建、安卓签名和控制台安装通过，已核对挑战值篡改时签名失败、同用户的签名密钥可复用、缺少 USB 网卡时能给出引导。MatePad 待解锁及确认覆盖安装，自动重连仍待真机验收。

- MatePad 12.7（320）已通过 ADB 非流式覆盖安装，沿用旧配对。已在 Windows 控制台邀请并在平板确认一次，进入独立副屏后从控制台断开。保留同一设备卡并再次从控制台点击「连接」，期间未触碰平板，Android 从 PcView 进入 Game，控制台确认同一设备以扩展模式在线。验收结束时保留该串流。USB 网络串流仍待支持 USB 共享网络的设备实测。

- GT6 已通过 USB 共享网络实测。控制台经 USB 扫描并邀请，手机确认出画面。Windows 识别 Remote NDIS，GT6 的控制连接和到设备的路由均走该接口，三秒内该接口发送约 1 MiB。第二路串流日志确认已连接并捕获 2200×1000。MatePad 第一块副屏同时沿用热点并继续在线，两路都为独立扩展。
- 新候选 Windows 安装包增加「USB 已连接」状态，依据实际控制通道所在网卡判定，构建和包内检查已完成。验收时保留两台串流，未重启本机控制台来应用状态文字。延迟尚无同设备、同配置的端到端对照数据。MatePad 本身仍未提供 USB 网卡，当前有线方案在 GT6 上验证。
